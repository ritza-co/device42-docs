Device42 sends system email through your own mail server, including alerts, scheduled reports, and password reset messages. This page is for administrators who configure that mail server, and it covers both authentication methods Device42 supports.

Go to **Tools > Settings > Mail Server Settings** to configure the connection.

## Authentication Types

Device42 supports legacy and modern mail server authentication:

- **Basic Authentication (Legacy):** Device42 authenticates with a username and password.
- **OAuth2 (Modern Authentication):** Device42 requests an access token from your identity provider and authenticates with that token. No password is stored.

Existing configurations continue to use basic password/username authentication after an upgrade, so your current mail settings keep working.

Microsoft has deprecated basic authentication for Exchange Online. If you relay mail through Microsoft 365, use OAuth2. Device42 cannot send mail through a Microsoft 365 relay once your tenant disables basic authentication. For details, see Microsoft's [Deprecation of Basic authentication in Exchange Online](https://learn.microsoft.com/en-us/exchange/clients-and-mobile-in-exchange-online/deprecation-of-basic-authentication-exchange-online).

## Configure Basic Authentication

Complete the following fields:

- **Mail Server IP or FQDN:** The address of your mail server, such as `smtp.gmail.com`.
- **Use TLS:** Select this option to encrypt the connection to the mail server.
- **Port:** The port your mail server listens on. TLS connections normally use port `587`.
- **Username:** The account Device42 authenticates with.
- **Password:** Select a stored password, or click the **plus icon** to add one.
- **Mail Address From:** The address that Device42 sends system email from.
- **SSL Verification:** Select this option to verify the mail server's certificate.

Click **Save**, then click **Test Mail Server** to confirm the settings.

## Configure OAuth2 for Microsoft 365

Device42 sends mail through Microsoft 365 using client SMTP submission. To authenticate with OAuth2, register Device42 as an application in your Microsoft Entra ID tenant, then enter the registration values in Device42.

Confirm the following before you start:

- SMTP AUTH is enabled on the mailbox Device42 sends from. Microsoft disables SMTP AUTH by default for tenants created after January 2020. See [Enable or disable authenticated client SMTP submission](https://learn.microsoft.com/en-us/exchange/clients-and-mobile-in-exchange-online/authenticated-client-smtp-submission).
- The mailbox is licensed, and its address is the one Device42 sends from.

### Register Device42 in Microsoft Entra ID

Create the app registration in the same tenant as the Microsoft 365 mailbox that Device42 sends from. Microsoft documents the process in [Authenticate an IMAP, POP, or SMTP connection using OAuth](https://learn.microsoft.com/en-us/exchange/client-developer/legacy-protocols/how-to-authenticate-an-imap-pop-smtp-application-by-using-oauth).

1. In the [Microsoft Entra admin center](https://entra.microsoft.com), register a new application for Device42. Keep the default settings.
2. Go to **Manage > Certificates and secrets** and create a client secret. Copy its value immediately, as Microsoft shows it only once. Note the expiry date you set.
3. Go to **Manage > API permissions** and add the **SMTP.SendAsApp** application permission. This permission is on the **Office 365 Exchange Online** API, not the Microsoft Graph API.
4. Grant admin consent for the permission.
5. Record the **Application (client) ID**, **Object ID**, and **Directory (tenant) ID** from the application's overview page, along with the secret value from step 2.

Device42 cannot send mail after the client secret expires. Create a new secret and update the mail server settings before that date.

### Register the Service Principal in Exchange Online

Register the application in Exchange Online so it can access the mailbox. Run the following commands in Windows PowerShell as an administrator, substituting the values you recorded:

<details>
  <summary>Click to expand the code block</summary>

```powershell
Install-Module -Name ExchangeOnlineManagement -allowprerelease
Import-Module ExchangeOnlineManagement
Connect-ExchangeOnline -Organization <tenant-id>
New-ServicePrincipal -AppId <client-id> -ObjectId <object-id>
```

</details>

Run `Get-ServicePrincipal | fl` to confirm the service principal exists.

Next, give the service principal access to the mailbox Device42 sends from. This step requires the Microsoft Graph PowerShell module:

<details>
  <summary>Click to expand the code block</summary>

```powershell
Install-Module Microsoft.Graph -Scope CurrentUser
Add-MailboxPermission -Identity "<mailbox-address>" -User <object-id> -AccessRights FullAccess
```

</details>

### Enter the OAuth2 Settings in Device42

Select OAuth2 as the authentication type. Device42 then asks for the values from your app registration instead of a password:

- **Tenant ID:** The Directory (tenant) ID from your app registration.
- **Client ID:** The Application (client) ID from your app registration.
- **Client Secret:** The secret value you copied when you created the client secret.

Set **Mail Server IP or FQDN** to `smtp.office365.com` and **Port** to `587`, and select **Use TLS**. Microsoft requires TLS 1.2 or later for client SMTP submission. Set **Mail Address From** to the mailbox you granted the service principal access to.

Device42 requests an access token before each SMTP session and requests a new one when the current token expires. You do not need to refresh tokens manually.

## Test the Mail Server

Click **Test Mail Server** to confirm the configuration. This works with both authentication types.

If an OAuth2 test fails, check the following in your app registration:

- The **Client Secret** matches a current, unexpired secret in Entra ID.
- The **Tenant ID** and **Client ID** match the values on the application's overview page.
- The application has the **SMTP.SendAsApp** permission, and an administrator granted admin consent.
- The service principal is registered in Exchange Online and has access to the sending mailbox.
- SMTP AUTH is enabled on the sending mailbox.
