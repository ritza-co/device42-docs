This page is for administrators who want Device42 to notify another system when something changes in their infrastructure. By the end, a Device42 event such as a new, changed, or deleted device automatically sends a webhook to the endpoint you choose.

Webhooks initiate an external action in another part of your IT environment when an event occurs, based on rules you define. Also known as HTTP callbacks, webhooks are sent to HTTP endpoints (URLs) when a configured **Webhook Action** criteria is met. Within Device42, anything that produces an audit log entry can trigger a webhook.

For example, you can trigger a webhook when a Device42 discovery job finds a new device, when details about an existing device change, or when an existing device is deleted. An administrator might configure a webhook to deliver a message to IT employees through a webhook-compatible endpoint such as Slack, letting them know that the action took place.

## Prerequisites

Before creating a webhook, make sure you have:
- Access to Device42 to configure **Tools > Webhooks**
- An HTTP endpoint URL to receive the webhook, such as a Slack, Zapier, or custom endpoint
- Any header names and tokens your endpoint requires for authentication

## Create a Webhook Action in Device42

Configuring Device42 to send a webhook is a simple two-step process:

1. Define one or more **Webhook Endpoints:** the HTTP URLs Device42 should send your webhooks to via **Tools > Webhooks > Endpoints > Add Webhook Endpoint**.

![Add a webhook endpoint](/assets/images/WEB-806_1.png)

2. Define a **Webhook Action:** the Device42 action(s) that will trigger your webhook, and the endpoints they should go to via **Tools > Webhooks > Actions > Add Webhook Actions**.

![Add a webhook action](/assets/images/WEB-806_2.png)

## Webhook Options

### Webhook Action Screen Options

The following options are available on the webhook action screen:

- **Name:** A name you define for the webhook action.
- **Process All Categories:** Hides the **Available Categories** choices. Webhooks fire on changes in all categories.
- **Available Categories:** Specify the object categories that trigger the webhook.
- **Process Add Events:** Trigger a webhook when a new object is added to a chosen category.
- **Process Delete Events:** Trigger a webhook when an object in any chosen category is deleted.
- **Process Change Events:** Trigger a webhook when an object in any chosen category is changed.
- **Process View Events:** Trigger a webhook when a view event is logged on an object in a chosen category.
- **Process Login Events:** Trigger a webhook when a login event is recorded on an object in a chosen category.
- **Destination:** Choose the endpoints that receive triggered webhook events.

### Webhook Endpoint Screen Options

The following options are available on the webhook endpoint screen:

![Webhook endpoint screen options](/assets/images/WEB-806_3.png)

- **Name:** A name you define for the webhook endpoint.
- **URL:** The URL destination for the webhook.
- **Endpoint:** Choose **Slack** or **Zapier** to reveal fields specific to those endpoints. Choose **Custom** for anything else.
- **Channel:** Slack endpoint only. Specify the Slack channel that receives the message when the webhook is received.
- **Username:** Slack endpoint only. Specify the Slack username the message originates from.
- **Icon:** Slack endpoint only. Specify a custom icon for the sender.
- **Webhook Header:** Define custom header payloads. Each includes a **Name** and a **Token** field that you define.
